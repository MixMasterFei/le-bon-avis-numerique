The site has solid SEO foundations — proper sitemap, robots.txt, JSON-LD on media pages, and lang attribute. The main actionable issues are: a **title duplication bug** on 6 static pages (the layout's title template is applied on top of strings that already contain "| Totem Avisé"), several **client-only pages without SSR metadata** that appear in the sitemap, and missing `og:locale` on listing pages.

## Issues Found

### Critical

1. **Title duplication bug on 6 pages** — Pages that hardcode ` | Totem Avisé` in their title string also have the layout's `template: "%s | Totem Avisé"` applied, producing titles like `"À propos | Totem Avisé | Totem Avisé"`.
   - Affected: `a-propos`, `notre-methode`, `objectif`, `nos-valeurs`, `bd`
   - Affected: `blog/[slug]` — `"${title} — Blog Totem Avisé | Totem Avisé"`
   - **Fix:** Replace `title: "Page | Totem Avisé"` with `title: { absolute: "Page | Totem Avisé" }` on all affected pages, OR remove ` | Totem Avisé` from the string and let the template add it.

2. **Client-only pages in sitemap have no SSR metadata** — `/livres`, `/collections`, `/recommandations`, and all 6 `/age/*` pages are `"use client"` components with no `generateMetadata`. Google will see no server-rendered `<title>` or `<meta description>` for these pages.
   - **Fix:** Convert the page file to a server component wrapper that exports `generateMetadata` and passes data down to a client component child. The listing logic can stay client-side.

### High

3. **`og:locale` and `og:type` missing on listing pages** — The films, series, and jeux pages define a partial `openGraph` object without `locale` or `type`. In Next.js, a page-level `openGraph` object replaces (not merges) the layout's openGraph, so `fr_FR` locale is lost.
   - **Fix:** Add `locale: "fr_FR"`, `type: "website"`, `siteName: "Totem Avisé"` to the `openGraph` objects in `films/page.tsx`, `series/page.tsx`, and `jeux/page.tsx`.

4. **Missing canonical tags on static info pages** — `/a-propos`, `/notre-methode`, `/objectif`, `/nos-valeurs`, `/guides` have no `alternates: { canonical }`. Without a canonical, these pages may inherit the root canonical `/` which would confuse crawlers.
   - **Fix:** Add `alternates: { canonical: "/a-propos" }` etc. to each page's metadata.

### Medium

5. **Short meta descriptions** — Multiple pages have descriptions under the 120-char recommendation:
   - Global default: 119 chars (1 under)
   - Series page: 108 chars
   - Jeux page: 115 chars
   - `notre-methode`: 98 chars
   - `a-propos`: 110 chars
   - `objectif`: 104 chars

6. **`images: { unoptimized: true }` in next.config.ts** — This disables Next.js image optimization entirely (no WebP, no srcset, no size-appropriate delivery). Significantly impacts LCP/page speed and Core Web Vitals scores, which are a Google ranking factor.
   - **Fix:** Remove `unoptimized: true` and configure proper `remotePatterns` only (already done). Test that TMDB/IGDB images still load correctly.

7. **No `WebSite` JSON-LD with SearchAction** — A `WebSite` schema with `potentialAction: { "@type": "SearchAction" }` enables Google Sitelinks Search Box, increasing SERP real estate.

### Low

8. **`/bd` page missing from sitemap** — `src/app/bd/page.tsx` exists and is potentially indexable but is not listed in `sitemap.ts`.

9. **Blog listing not always in sitemap** — The `/blog` URL is added to the sitemap only when Sanity has published posts. The page exists regardless and should be in the sitemap unconditionally.

10. **`/studio` not in robots.txt disallow** — Sanity Studio at `/studio` is crawlable. While it won't expose sensitive data, it wastes crawl budget and is irrelevant content for search engines.

11. **`/jeux-video` returns 404** — CLAUDE.md documents the games section as `/jeux-video`, but the actual page is at `/jeux`. No redirect exists for `/jeux-video`. Any external link pointing to `/jeux-video` will 404.

12. **Blog description 1 char over limit** — Blog listing meta description is 161 chars (recommended max: 160).

13. **OG image not 1200×630** — The shared OG fallback image `/icon.png` is 620×606, not the standard 1200×630. This won't prevent sharing but produces suboptimal previews on Facebook and LinkedIn.

## Recommendations

**Priority 1 (this sprint) — fixes are small and high-impact:**

```typescript
// Fix 1: Title duplication — use { absolute: ... } to bypass template
// e.g. src/app/a-propos/page.tsx
export const metadata = {
  title: { absolute: "À propos | Totem Avisé" },
  description: "...",
  alternates: { canonical: "/a-propos" },
  openGraph: {
    title: "À propos | Totem Avisé",
    description: "...",
    locale: "fr_FR",
    type: "website",
    siteName: "Totem Avisé",
    images: [{ url: "/icon.png", width: 620, height: 606, alt: "Totem Avisé" }],
  },
}
```

```typescript
// Fix 2: Add og:locale + type to listing pages
// src/app/films/page.tsx — inside generateMetadata return
openGraph: {
  title: `${title} | Totem Avisé`,
  description,
  locale: "fr_FR",
  type: "website",
  siteName: "Totem Avisé",
  images: [{ url: "/icon.png", width: 620, height: 606, alt: "Totem Avisé" }],
},
```

**Priority 2 (next sprint) — requires more work:**

- Convert `/livres`, `/collections`, `/recommandations`, and `/age/[range]` to server-component wrappers with `generateMetadata`, keeping the interactive logic in a child client component.
- Lengthen short meta descriptions to 120–160 chars for all affected pages.
- Add `alternates: { canonical }` to the static info pages without canonicals.

**Priority 3 (backlog):**

- Create a proper `WebSite` JSON-LD with `SearchAction` on the homepage.
- Add `/studio` to robots.txt disallow list.
- Add `/bd` to sitemap and ensure `/blog` is always included.
- Create a dedicated OG image (1200×630) for the site logo and listing pages.
- Investigate removing `images: { unoptimized: true }` — this has a significant performance impact. If it was added to work around an image loading issue, document the root cause.
- Add a 301 redirect `/jeux-video` → `/jeux` in `next.config.ts` to catch any inbound links.
